# 接口文档响应字段树规则设计

## 1. 背景

阶段 2.1 至 2.5 已完成接口文档维护入口、文档状态、草稿与完成维护校验、后台表单拆分和请求参数所有权边界。当前响应字段已经通过编辑会话内的 `paramKey`、`parentParamKey` 表达父子关系，后端也具备基础的缺失父级、循环引用、同级重名和八层深度校验，但仍存在以下缺口：

- 后端允许标量响应字段拥有子字段。
- 缺失父级错误没有指出缺失键及受影响的子字段。
- 前端父字段候选未排除标量字段、当前字段的后代和超深组合。
- 前端允许把拥有子字段的容器改为标量。
- 前端删除非叶子字段时会静默删除当前字段并把直接子字段提升为根字段，管理员无法确认影响范围或选择处理方式。

本设计只落实落地计划 2.6“响应字段树规则”，不提前实现 2.7 的聚合保存边界、2.8 的数量和文本长度上限或后续发布探测能力。

## 2. 目标与非目标

### 2.1 目标

- 响应字段树最大深度为八层，根字段深度计为第一层。
- 只有 `object`、`array` 类型的响应字段可以拥有子字段。
- 前后端共同拒绝缺失父级、标量父级、循环引用、同级重名和超过八层的结构。
- 删除非叶子字段前展示全部后代字段，并提供“删除整个子树”“提升直接子字段”“取消”三个明确操作。
- 树操作仅在完整校验通过后一次性应用，校验失败时不得部分修改编辑状态。
- 后端错误能够定位缺失的父级键和每组受影响的子字段。

### 2.2 非目标

- 不改变统一响应外壳或下游接口响应协议。
- 不移除 `array` 类型。即使响应采用 `code`、`data`、`message` 外壳，`data` 本身或其内部字段仍可能是数组。
- 不提供删除节点后把子字段迁移到任意指定父节点的第四种操作。
- 不把数据库 `parentId` 暴露为前端编辑会话的稳定业务键。
- 不调整网关、SDK、在线调试或发布探测链路。
- 不在本轮引入拖拽排序、批量导入或从 JSON 示例生成字段树。

## 3. 核心定义

### 3.1 节点身份

`paramKey` 是一次前端编辑会话内的节点标识。已有数据库记录在加载时使用记录 ID 派生会话键，新增节点使用前端生成的会话键。保存请求只通过 `parentParamKey` 引用同一请求中的父节点，后端落库时继续将会话关系转换为数据库 `parentId`。

`paramKey` 不跨加载稳定，不能作为数据库业务主键、并发修订号或跨请求引用。

### 3.2 容器与标量

容器类型为 `object`、`array`。标量类型为 `string`、`number`、`boolean`。类型值沿用现有协议的小写标准值。

`array` 节点的子字段表示数组元素对象的字段结构。例如 `data.users` 为数组时，可以拥有 `id`、`name` 子字段。本轮不新增数组元素类型字段。

### 3.3 深度

根字段深度为一，子字段深度为父字段深度加一。最大允许深度由后端独立常量 `MAX_DOC_NESTING_DEPTH = 8` 表达，与 JSON 示例安全扫描的 64 层限制无关。

### 3.4 字段路径

前端展示受影响字段和父字段候选时使用从根节点开始的完整路径，各路径段优先使用字段名；字段名为空时回退为 `paramKey`。路径用英文句点连接，例如 `data.users.name`。

路径只用于界面展示和错误定位，不参与节点匹配或保存。

## 4. 后端设计

### 4.1 校验入口与顺序

聚合保存继续由 `InterfaceDocServiceImpl.saveDoc` 控制事务。参数基础字段校验完成并建立 `paramKey` 映射后，按以下顺序校验和构建关系：

1. 收集所有声明了 `parentParamKey` 但父节点不存在的响应字段。
2. 按缺失的 `parentParamKey` 分组生成错误信息，并终止保存。
3. 关联存在的父子节点，确认父子节点均属于响应字段场景。
4. 校验所有拥有子字段的节点类型只能是 `object` 或 `array`。
5. 校验同一父级下的字段名不重复。
6. 沿父链检测循环引用并计算节点深度。
7. 拒绝深度大于 `MAX_DOC_NESTING_DEPTH` 的响应字段。
8. 按深度和 `sortOrder` 排序，供现有父节点先落库流程使用。

任一校验失败都在参数替换前抛出业务异常，聚合保存事务不会删除或写入部分文档数据。

### 4.2 缺失父级错误

错误信息按缺失父级键分组，并列出每组直接引用该键的子字段。子字段优先显示名称，名称为空时显示 `paramKey`。示例：

```text
响应字段父级不存在：missing-a -> [name, response-3]；missing-b -> [detail]
```

分组和字段列表采用请求中的稳定顺序，避免错误信息顺序随哈希结构变化。

### 4.3 标量父级错误

父节点拥有一个或多个子节点但类型不是 `object`、`array` 时，返回包含父字段显示名和实际类型的参数错误。例如：

```text
响应字段 data 的类型 string 不能拥有子字段
```

后端不信任前端禁用状态或即时校验，Controller 请求与 Service 直接调用均执行相同规则。

### 4.4 循环、同级重名和深度

循环引用继续通过递归访问链检测。同级重名按同一父节点的字段原始名称判断，根字段共享空父级。深度只对响应字段树计算，错误文本统一使用“响应字段”，避免与运行时请求参数混淆。

## 5. 前端设计

### 5.1 树工具

新增无界面的响应字段树工具模块，集中提供以下纯函数：

- 建立节点映射和子节点索引。
- 计算节点完整路径。
- 获取直接子字段和全部递归后代。
- 判断节点是否为容器。
- 生成可选父字段列表，排除自身、全部后代、标量节点和会导致深度超限的节点。
- 校验缺失父级、标量父级、循环引用、同级重名和八层深度。
- 生成“删除整个子树”和“提升直接子字段”后的候选快照。

工具函数不得直接修改传入数组或节点对象。页面只在候选快照通过完整校验后替换 `responseParams`。

### 5.2 类型和父级变更

响应字段编辑器仍通过事件向维护页请求更新，不直接拥有全局编辑状态。

- 容器节点存在子字段时，如果管理员把类型改为标量，维护页拒绝更新，选择框保持原类型并显示具体错误。
- 修改父字段时，维护页先构建候选快照，再执行完整树校验；校验失败时保留原父级。
- 父字段下拉框只展示合法候选，并使用完整路径作为标签。
- 树结构错误使用维护页现有错误区域展示，不通过静默回滚隐藏原因。

### 5.3 删除叶子字段

叶子字段没有后代，点击删除后可以直接从编辑快照移除，不显示子树处理弹窗。

### 5.4 删除非叶子字段

点击非叶子字段的删除按钮后，页面保存待删除节点及其全部后代快照，打开专用对话框。对话框必须：

- 使用 `role="dialog"` 和 `aria-modal="true"`。
- 显示待删除字段的完整路径。
- 按稳定的树遍历顺序列出全部直接及递归后代路径。
- 提供“删除整个子树”“提升直接子字段”“取消”三个按钮。
- 支持关闭按钮和 Escape，二者语义均为取消。

对话框打开期间不修改 `responseParams`。

### 5.5 删除整个子树

管理员明确选择后，候选快照移除当前节点及全部后代。校验通过后一次性替换当前响应字段数组并关闭对话框。

### 5.6 提升直接子字段

管理员明确选择后，候选快照只移除当前节点：

- 当前节点存在父级时，其直接子字段的 `parentParamKey` 改为当前节点原来的父级键。
- 当前节点是根字段时，移除其直接子字段的 `parentParamKey`，使其成为根字段。
- 孙级及更深节点的 `parentParamKey` 保持不变。

候选快照必须重新校验父级存在、父类型、循环引用、同级重名和最大深度。如果提升导致同级重名或遇到已有非法父结构，操作失败、原数组保持不变，对话框保持打开并展示错误。

### 5.7 保存前校验

“保存草稿”和“完成维护”都在现有表单校验中执行完整响应字段树校验。即时交互校验用于尽早反馈，保存前校验用于防止加载异常数据或未来新增交互绕过规则；后端仍是最终权威。

## 6. 数据流

```text
聚合详情 parentId
  -> 前端加载时转换为会话 paramKey/parentParamKey
  -> 管理员编辑响应字段树
  -> 树工具生成并校验候选快照
  -> 前端提交全量 paramKey/parentParamKey 快照
  -> 后端重新建树并执行权威校验
  -> 父节点按深度优先落库
  -> parentParamKey 转换为数据库 parentId
```

## 7. 错误处理

- 前端树操作失败时不应用候选快照，保留管理员现有数据并显示可操作的错误信息。
- 删除对话框关闭或取消时不产生脏数据变化。
- 后端结构错误统一使用参数错误，不泄露数据库 ID、堆栈或内部实现细节。
- 缺失父级错误可以包含本次会话的 `paramKey`，但不得把数据库 `parentId` 作为稳定业务标识返回。
- 聚合保存失败沿用现有错误展示和事务回滚行为。

## 8. 测试设计

### 8.1 后端测试

- `object` 和 `array` 父字段分别允许拥有子字段。
- `string`、`number`、`boolean` 父字段拥有子字段时保存失败。
- 八层响应字段树保存成功，九层保存失败。
- 循环引用和同级重名继续失败。
- 多个缺失父级按键分组，错误包含全部受影响字段名称或回退键。
- Service 直接调用不能绕过标量父级和深度规则。
- 校验失败后原文档参数保持不变，验证事务和校验时机。

### 8.2 前端树工具测试

- 完整路径生成与未命名节点回退。
- 递归后代收集顺序。
- 父字段候选排除自身、后代、标量节点和超深节点。
- 标量父级、缺失父级、循环、同级重名、八层和九层校验。
- 删除整个子树不保留后代。
- 提升直接子字段只改直接子级，更深关系不变。
- 提升到父级和提升到根级两种结果。
- 提升导致同级重名时拒绝候选快照。

### 8.3 前端组件与页面测试

- 有子字段的容器改为标量时立即阻止。
- 叶子字段直接删除且不打开对话框。
- 非叶子字段对话框列出全部后代完整路径。
- 三个对话框操作分别覆盖删除整个子树、提升直接子字段和取消。
- 保存前拒绝异常字段树，合法树可以提交。
- 对话框可访问性属性、关闭按钮和 Escape 行为。
- 既有草稿、完成维护、脏状态和保存重载行为不回归。

### 8.4 验证命令

- 后端执行接口文档 Controller 定向测试及相关 Service 测试，随后执行后端模块测试。
- 前端执行树工具、响应字段编辑器和维护页定向测试。
- 前端执行全量单元测试、类型检查、ESLint 和生产构建。
- 两个仓库执行 `git diff --check`。
